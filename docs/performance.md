# 显示帧率优化（2026-10-09）

目标：实际完成传屏的 display_fps 稳定超过 15，同时保留正常游戏速度、声音和竖屏 240×225 完整画面。emu_fps 接近 60 不能代替这个目标。

阶段收尾结论：最终真机七款范围 13.9–19.6 fps，严格目标未全面达成；最终结果见末节。下文先后版本的“待测”属于当时状态。

红白/异步绘屏版的用户游玩日志 `.work/playtest-redwhite-1.log`：F-1 15 fps、热血足球 3.3–11.4、双截龙 7.5–15、魂斗罗 3.8–10.8、超级马里奥 7.4–12.6。范围为各 10 秒统计窗口，包含不同阶段，未建立相同操作回放。用户反馈音频流畅、画面仍不够流畅，不能视为性能验收通过。

## 当前修改

1. APU 的四类相位累加器和每采样周期改为有符号 Q16 定点。周期在初始化时用 64 位整数四舍五入；热循环只做整数算术。样本率仍为 16 kHz、每帧仍为 266/267 样本，没有重复/拉长样本。RISC-V APU 对象反汇编未见软件浮点运算调用。
2. 仅 CPU 解释器源文件加 `-fjump-tables -ftree-switch-conversion`，恢复 256 个 opcode 的索引分派；该函数不放入 IRAM，也不从中断调用。编译命令和反汇编均核对。
3. 绘屏间隔按“距上次实际绘制的帧数”计数；LCD 忙时延后的机会不会因错过固定模数而再次等待。负载恢复阈值改为 14 ms，避免进入 8 帧间隔后在 13 ms 负载下无法恢复。

未增加完整帧缓冲、未超频、未更改 SPI 时钟或降低游戏分辨率。实现只修改现有代码，没有拷入上述外部仓库的新源码。

## 跳过绘制时的精灵扫描优化

`ppu_renderoam` 原先在不绘制的扫描线上仍搜索最多 64 个精灵。无 Mapper latch 回调时，唯一需要保留的效果是精灵 0 命中检测：现在只检查精灵 0，已命中则直接返回。有 latch 回调时仍完整执行原路径，实际绘制路径不变。未改变既有跳帧命中近似算法，也未改变音频、分辨率、显示缓冲或硬件时钟。

基线代码保存在 `.work/perf-q16-baseline`，应用/ELF 保存在 `build/verification/q16-before-ppu/`。主机测试 8 组通过；八款各 3,600 帧固定输入的画面汇总哈希一致，每款 960,000 音频样本逐一相同。PassportSim 测试入口 6 项通过，保留既有屏幕睡眠时序警告；模拟机不能证明真机性能增幅。

生产镜像 `build/preloaded/FC-1.0-8genres-perf-ppu.bin` SHA256 `ecb1663255c3403dc1f4e39cbab4fcacda28a248c91eb010dff85ce2bdc94e7e`；应用 2,518,688 字节、SHA256 `2d5cd494bac3fa845c40553e6fe55367e1cfab20f66c3cb783ab67b899ac3707`；ELF SHA256 `e206f48c3178c2ae9b8be086c5f76bc3d710ee2958090e4ff2503e41d1b19f6f`。构建和镜像布局验证通过，新版本实际显示帧率待游玩验证。
