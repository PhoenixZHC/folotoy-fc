# Wi-Fi 管理后游戏启动失败（2026-10-10）

> 当前 FC 1.5 完整包与设备身份见 [交付说明](release-1.5.md)，验收边界见 [验证记录](validation.md)。本页版本、哈希和测试结论保留其历史时点或专题范围。

## 复现与证据

用户复现：正常启动游戏并退出，进入 Wi-Fi 管理后返回，再启动游戏即报“游戏不支持/内存不足”；重启恢复。不需要上传或删除 ROM。

COM14 诊断日志 `.work/com14-wifi-diag.log`：首次启动总空闲 115564 字节、最大连续块 106496 字节；退出管理后总空闲 102176 字节、最大连续块 49152 字节。明确失败于 65280 字节的帧缓冲分配。ROM 校验和 Flash 映射成功。该问题与 Mapper 4 的 ROM 容量上限无关。

## 修复与验证边界

首次音频问题：用户直接启动《口袋怪兽 绿 绿叶版》时，`.work/com14-wifi-audio-extended.log` 明确记录 `i2s_alloc_dma_desc` / `ESP_ERR_NO_MEM`：核心已分配后才首次初始化 codec/I2S，DMA 缓冲分配失败。此前自动测试先运行小 ROM，已提前初始化音频，未覆盖该顺序。最终新增 `gb_audio_prepare()`，在核心分配前准备 I2S/codec；回归改为冷启动先开关 Wi-Fi，再逆序从大 ROM 开始。设备重连后该顺序回归已通过，正常应用用户操作验收已通过，见下文。

最终修复：帧缓冲按 4 行拆成 60 块，每块 1088 字节，PPU 和 LCD 按行指针访问；先申请必须连续的 PRG/CHR RAM，再申请画面小块。保留每行左右 overdraw 和显示借用期间的生命周期约束，不增加完整画面副本。Wi-Fi 生命周期保持原样。仅提前初始化网络的方案已由实机否定，不保留在最终实现中。

用户进一步验收发现 CHR RAM 游戏会提示“声音启动失败”。音频改用静态队列、静态信号量及静态工作栈，任务在停止后等待下一次启动通知，不反复删除/创建。入场动画复用现有显示队列缓冲，移除旧 GB 前帧比较缓存（5760 字节）；旧 GB/动画路径完整绘制各条带，FC 游戏渲染流程不因此增加传输。

15 组主机测试通过，包括限制单次分配不超过 8 KiB、65 个分配失败位置/边界的清理及重试、全行图像与跳帧不改像素检查。用户 ROM 600 帧烟测：3 款运行、5 款按既有 Mapper 限制拒绝、0 运行失败。ESP-IDF 5.5.3 构建通过。

COM14 最终自动回归：冷启动先开关 Wi-Fi，再从目录尾部大 ROM 开始运行，现有 10 款游戏共 4 轮、40 次检查全部成功；每次包含核心初始化、动画首尾帧、8 帧模拟、音频启动/提交/停止及 LCD 传输。包括首次冷启动在内共 4 次网络启停成功。日志 `.work/wifi-cold-audio-autotest.log`，对应测试应用/ELF 保存在 `.work/wifi-cold-test-artifact/`。该测试不包含实际 HTTP 上传和用户可见画面/按键/声音验收。

正常应用已关闭 `FC_WIFI_MEMORY_TEST`，标准 `tools/build.ps1` 显式关闭该开关，防止测试设置沿用。仅写应用分区 `0x10000`，分区表与正式 1.2 一致，未写设置、ROM 或存档分区。正式交付包未修改。

用户操作验收：2026-10-10 用户按“进入 Wi-Fi 管理 → 返回 → 打开口袋妖怪 → 暂停并恢复”的要求回复“正常了”。正常应用日志确认退出 Wi-Fi 后《口袋怪兽 绿 绿叶版》初始化成功，未再出现声音启动失败，音频停止记录正常。用户反馈作为画面、声音和操作验收证据；串口日志不单独证明主观音质。监听随后遇到设备断开，已停止重连并释放 COM14。

本次启动故障修复验收通过。实际 HTTP 上传/删除后的完整流程、长期运行和其他 ROM/外设组合未在本轮重新验收。随后按用户要求升级为 1.3，生成并校验原 16 款游戏的完整包，见 `release-1.3.md`；新完整包尚未烧录，未提交或推送 GitHub。
