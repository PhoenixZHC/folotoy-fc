# 小米蓝牙遥控器横握接入（FC 1.5）

日期：2026-10-14。[English](xiaomi-remote.en.md)。

本次实现用户指定的 FC 固件接入与映射。FC、GB/GBC 的游戏输入都是方向、A/B、Start/Select，没有肩键；本次没有修改 GameBoy 工程。

## 横握映射

方向按遥控器原有图标命名，连接识别成功后自动启用，菜单导航和游戏使用同一映射。

| 遥控器实体键 | 原始 Keyboard/Keypad usage | 游戏输入 |
|---|---|---|
| 右 | `0x4F` | 上 |
| 上 | `0x52` | 左 |
| 左 | `0x50` | 下 |
| 下 | `0x51` | 右 |
| TV | `0x35` / `0xC0` | A |
| 三条横线菜单／设置 | `0x65` / `0x5D` | B |
| 主页 | `0x4A` / `0x24` | Start |
| 返回 | `0xF1` | Select |

返回短按是游戏 Select；长按 1 秒打开暂停菜单或执行当前页面的返回操作，进入/恢复页面需先松开再长按。确认、电源、语音和音量键未分配游戏动作。

## 识别与使用

专用映射限定为键盘类 HID、VID/PID `0x2717:0x32B8`，不按名称给普通键盘或其他手柄旋转方向。该身份来自小米遥控器 2 / 2 Pro 的公开接入记录；具体实物型号、固件及有无 TV 键仍以设备为准，不能据此宣称同系列所有型号已适配。

按实物说明书进入蓝牙配对状态，在 FC 的配对列表选择对应设备。沿用现有 BLE 配对和 HID 服务发现流程；完整名称 `MI RC` / `Xiaomi RC` 在缺少 HID 广播 UUID 或 Generic Remote Control 类型时可进入待探测列表。名称只允许用户选择候选，连接后仍读取实际 HID Report Map、设备 VID/PID 并选择解析器。未发现支持的键盘/手柄描述符时断开，未知 VID/PID 不启用横握映射。

连接后进入“手柄测试”，所有外接设备使用原来的固定完整布局，不随遥控器隐藏肩键、摇杆、扳机或 X/Y；未提供的输入维持零。普通键盘映射后的输入同样更新该页。RC001 / 固件 2671 的八键和释放已由串口及用户实测确认；实测多键不可用。见 [修复记录](rc001-input-fix.md)。

## 实现与验证

复用 Bluepad32/BTstack 的描述符解析器，并对已实测 RC001 / FW2671 的声明 6 字节、实际 8 字节负载加入限定兼容分支；其他布局沿用描述符校验。返回 `0xF1` 在标准过滤前转换，完整当前集合替换旧状态，异常长度仍拒绝，ATVV 语音不参与。本次实物抓包/回归及多键边界见 [修复记录](rc001-input-fix.md)。

- 构建：ESP-IDF **5.5.3**，ESP32-C3、8 MiB、原分区，正式入口；三个诊断开关关闭。应用与 ELF 身份、完整镜像分区及回读一致性校验通过。
- 主机测试：当前 **26 组通过，0 失败**；包括真实 RC001 描述符/报告重放、映射和输入校验，以及主页标签、路由和入页持键回归。构造组合键只验证解析器能力，不证明实物同时报告多键。新增菜单测试修正测试桩头文件后单独重跑，复用其他 25 组有效结果，见 [菜单记录](menu-entry-fix.md)。
- 打包测试：**7 项通过，0 失败**。
- 设备烧录/启动：初始原 16 款游戏包按授权从 `0x0` 全新写入，随后抓包定位并修复 RC001 报告长度。最新菜单日常版仅更新 COM14 应用，保留游戏、存档、设置和配对；写入及版本 1.5/16 游戏/ELF 身份校验通过，监控未见 panic/abort/watchdog，串口已释放。用户确认八键单键正常、菜单测试通过；实物组合键不可用。当前身份见 [菜单交付](menu-entry-fix.md)，初始包见 [历史记录](release-1.5.md)。

用户已确认八键单键功能正常；抓包 124 个报告均最多一个非零键码，用户在《魂斗罗》里确认不能边移动边开枪。这只 RC001 / FW2671 不能作为需要组合键的完整手柄替代；固件没有增加伪造组合键或锁定/连发。其他型号和固件需另行验证。
