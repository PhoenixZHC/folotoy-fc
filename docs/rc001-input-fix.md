# RC001 无按键响应修复与固定测试页（2026-10-14）

[English](rc001-input-fix.en.md)。本记录替代此前“遥控器专用测试布局”和“遥控器功能待验收”的当前状态；历史镜像继续保留。

## 用户要求与界面

用户要求一个固定手柄测试页测试所有外接设备，不随遥控器隐藏摇杆、肩键、扳机或 X/Y。已恢复原完整布局，手柄、遥控器、普通 BLE 键盘共用；设备未提供的输入维持零值。键盘映射后的游戏输入也更新同一测试快照，单独的“当前连接为键盘”阻挡页面已去除。用户实测反馈测试页有反应，单键功能均正常。

## 原因与修复

COM14 实物身份为 **RC001，固件 2671，VID/PID 2717:32B8**。设备 Report Map 的报告 1 声明 `Report Count=3`、`Report Size=16`，即 6 字节按键负载；实际通知是标准键盘的 **8 字节**负载。BTstack 依据 Report Reference 加入 Report ID 后总长为 **9 字节**。

例如实体右键的真实输入是 `01 00 00 4F 00 00 00 00 00`，释放是 `01 00 00 00 00 00 00 00 00`。旧逻辑按描述符要求 7 字节，总是打印 `invalid HID input report id=1 len=9 expected=6`，并清空输入，导致连接成功却所有按键无反应。

修复仅作用于已识别小米设备、报告 ID 1、声明负载 6 字节、实际总长 9 且保留字节为零的格式。直接按 modifiers / reserved / 六个 8-bit usage 解码，并跳过本报告的 16-bit 描述符二次解析；归一化后复用原横握映射。其他报告仍按真实描述符解析，异常包长仍拒绝。普通键盘不经过该兼容分支。

测试使用本次实物的完整 86 字节描述符及八个实测键码重放：旧解析器能复现断言失败，修复后通过。组合包属于构造回归输入，与实物多键能力明确区分。

## 实测结果与限制

- 主机：**25 组通过、0 失败**，包含固定布局、键盘共用页面、实物格式重放、八键/释放、错误包、原映射回归。
- 构建/打包：ESP-IDF **5.5.3**、ESP32-C3、8 MiB、正式入口及原 16 款游戏；应用/ELF、分区边界和 ROM 哈希一致性校验通过。
- COM14：完整包从 `0x0` 写入并通过写入哈希校验；启动 `FC_READY version=1.5 games=16`，ELF 前缀 `eac20ced2...` 匹配，观察窗口未见 panic/abort/watchdog。
- 修复后串口：捕获 **124 个键盘报告**，八种映射输入及释放归零均已观察到，未再出现报告长度错误。
- 用户：确认“现在有反应了，按键功能都正常”；在《魂斗罗》中尝试同时操作，不能边移动边开枪。
- 实物报告中同时非零键码的最大数量为 **1**。这只 RC001 / 固件 2671 当前未提供可靠的多键同时保持状态，无法作为动作游戏的完整手柄替代。该限制不能靠普通映射补出；保留旧键会失去可靠的释放依据。本轮未增加锁定、连发或伪造组合键。
- 监控已结束，**COM14 已释放**。GameBoy 工程未修改；未提交或推送。
