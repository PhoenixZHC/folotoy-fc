> 当前 FC 1.5 完整包与设备身份见 [交付说明](release-1.5.md)，验收边界见 [验证记录](validation.md)。本页版本、哈希和测试结论保留其历史时点或专题范围。

2026-10-10 后续烧录：用户明确要求将 1.2 完整包写入 COM14，已从 0x0 覆盖 8 MiB 并通过写入哈希校验。25 秒启动日志确认 `App version: 1.2`、ELF `de13f155d…`、`FC_READY version=1.2 games=16`，未见 panic/assert；观察结束释放串口。此为烧录与启动验收，不扩展为全部游戏游玩验收。

收尾更新：用户于 2026-10-10 明确反馈“我测过了就是rom有问题”，将翡翠版画面异常按用户复测结论归为该 ROM 问题。本代理未独立完成跨模拟器对照，不宣称已修复图形核心；下文保留此前观察。容量修改纳入 [1.2 正式交付](release-1.2.md)，随后已按用户要求烧录正式 1.2 原 16 款包并验证启动；两款诊断包的结果不扩展为正式包逐款游玩验收。

用户要求将程序 ROM 容量上限从 512 KiB 放宽至 1.5 MiB，并在 COM14 测试。固件 `fc_rom_parse` 与打包工具 `validate_rom` 均允许最多 96 个 16 KiB PRG 块。CHR ROM 上限仍为 256 KiB，其他 Mapper、RAM、文件完整性与存储空间检查不变。没有修改 ROM 或扩大分区。

## 原问题与验证

- 皮卡丘Y2K：Mapper 4，128 KiB PRG + 128 KiB CHR，原本在允许范围内。主机可加载，3600 帧有画面/音频；原用户设备的“不支持/内存不足”仍需真机复现，统一报错本身不能证明 RAM 耗尽。
- 口袋怪兽翡翠版：Mapper 4，1 MiB PRG，CHR RAM，文件长度 1048592 字节正确。修改前核心返回 `ROM_REJECTED`，因为超过原 PRG 上限。截图选中的名称为“口袋宝石 红.nes”，与本附件不同，不将附件结论扩展为截图文件的确切原因。
- 修改后 14 组主机测试、7 项打包测试通过，包含 1.5 MiB 上限、超过上限、截断文件以及高位 PRG 块/固定末尾块寻址。ESP-IDF 5.5.3 正式构建和镜像布局校验通过。
- 两份真实 ROM 各运行 3600 帧：皮卡丘有正常非单色输出；翡翠版可加载且有画面变化/音频，但终点为单色，标为待确认，不能宣称游戏完整兼容。120/600 帧补充采样有多色输出，1800 帧也为单色；固定自动输入不等于人工验收。

## 真机验收

串口观察文件：`.work/mapper4-com14-test.log`，26912 字节；监听已停止、COM14 已释放。

- 皮卡丘：出现 `ROM loaded` 和连续运行/按键日志，display_fps 16.0–17.1，audio_drops=0；原“不支持/内存不足”未复现。用户尚未单独确认画面和完整游玩结果。
- 翡翠版：出现 `ROM loaded` 和连续运行/按键日志，display_fps 19.3–19.9；有累计 3 个音频丢块，最长音频等待约 178 ms。用户反馈画面有问题；主机 120 帧为正常科泰标志，600 帧截图有文字/图形错乱，后续有单色输出。标记为已加载但图形兼容性未通过，不能宣称问题全部解决，也不能据此断言 ROM 损坏。
- 本次观察未见 panic/assert 或启动内存不足；这一结论仅覆盖采样窗口。尚未在独立成熟模拟器对同一 ROM 做对照，画面异常根因未定位。
- 网页实际上传、存档/读档及长期稳定性尚未验收。预装成功不能替代 HTTP 上传验收。
